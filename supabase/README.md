## Local setup after the project is selected

Install the Supabase CLI using the official instructions for the developer's OS. From the repository root, run:

```bash
supabase login
supabase init
supabase link --project-ref tglnolhzjapcbkzdwybe
supabase start
supabase migration new catalog_foundation
```

Write the reviewed SQL into the timestamped file generated by the CLI. Validate it locally with `supabase db reset` before deploying. Then preview and apply to the linked Naffeez project:

```bash
supabase db push --dry-run
supabase db push
supabase gen types --lang typescript --linked > src/lib/supabase/database.types.ts
```

Do not use `supabase db reset --linked`; it is destructive. Do not push an unreviewed schema directly to the remote project.

## Initial schema scope

The logical source of truth is the Phase 2 Database Schema at docs/phase-2/DATABASE_SCHEMA.md. The implementation migration must include, at minimum:

- Categories and product taxonomy.
- Products, product media and per-image optional zoom metadata (zoom_storage_path, detail_label, optional variant_id).
- Product variants and SKU-level inventory levels/movements/reservations.
- Collections and collection-product ordering.
- Store settings and private admin membership/audit boundaries.
- Public read grants and RLS for published catalog records only.
- Admin writes only through an authenticated, authorized server path.
- A private `product-media` Storage bucket. The storefront adapter now requests 1-hour signed URLs for product/zoom assets. The migration must add a Storage SELECT policy that only permits objects referenced by published products (and active variants where applicable); create the bucket only with that policy in place.
- QR/payment-proof and invoices remain private and are deferred until their relevant features and policies are implemented.
- A database test plan for anonymous public reads, customer ownership and admin-only operations.

## Important implementation/security boundary

- Public catalog pages use `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` with explicit grants and RLS; missing env configuration produces the app's setup/empty state.
- SUPABASE_SECRET_KEY is server-only. Never prefix it with NEXT_PUBLIC_, return it from a route or import the server admin client into a Client Component.
- Never trust a client-side role, price, stock count, payment state or order total.
- Do not implement admin CRUD until the membership table, owner-approved role policy, storage policies and audit writer have been applied and tested.
- Do not enable checkout until shipping/COD/QR/stock-reservation and invoice owner decisions are resolved.
